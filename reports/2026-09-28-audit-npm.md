## 2. Installation

### 2.1 Via `npx` (parcours du README)

```bash
npx docpensieve init my-site     # 21 s au premier appel (téléchargement), 1,1 s ensuite
cd my-site && npx docpensieve dev
```

- ✅ `--help`, `--version` (0.4.1) et l'aide de chaque commande sont clairs.
- ✅ `init --yes` crée `docpensieve.config.mjs` (entièrement commenté), `.gitignore`,
  `docs/v1.0/` (2 pages) et `99-docpensieve/` (35 pages de doc de l'outil).
- ✅ Relancer `init` sur un dossier existant refuse proprement (exit 1, suggère
  `--force`) ; `--theme bootstrap` est refusé (exit 1, rien n'est écrit).
- ✅ Sans TTY (`echo | npx docpensieve init`) : valeurs par défaut, pas de blocage.

### 2.2 Installation épinglée (`npm init -y && npm install docpensieve`)

- ✅ 178 paquets en 3,4 s, **0 vulnérabilité** (`npm audit`).
- ℹ️ `node_modules` : **50 Mo**, dont `@shikijs` 14 Mo, `react-dom` 7,9 Mo,
  `shiki` 4 Mo, `handlebars` 3,9 Mo. `tailwindcss` est installé même en thème
  `custom`.
- ✅ Chaque paquet publié contient `LICENSE`, `README.md`, `src`, `types`.

### 2.3 Problèmes d'installation

| #   | Gravité | Constat                                                                                                                                                                                                                                                                                                                                                                         |
| --- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| I1  | 🟠      | **La page `guide/installation` générée par `init` dit `npm install` puis `npm run dev`, mais `init` n'ajoute aucun script au `package.json`** : `npm run dev` échoue (`Missing script: "dev"`). Même chose en 0.5.0-beta.5 et sur `main` (`packages/cli/src/commands/init.js:562-565`). Corriger le texte (`npx docpensieve dev`) ou ajouter les scripts `dev`/`build`/`check`. |
| I2  | 🟡      | `init --site-url "pas une url"` est accepté et écrit une config qui **ne build pas** ensuite (`siteUrl is not a URL`). Valider au moment d'`init`, comme `--theme`.                                                                                                                                                                                                             |
| I3  | 🟡      | Sans installation locale, chaque `npx docpensieve …` résout la dernière version sur le réseau (`npm warn exec … will be installed`) : lent hors ligne et la version peut changer entre deux commandes. Le README le signale à moitié ; recommander l'installation épinglée pour un projet réel.                                                                                 |

Vérifié sans problème : YAML invalide, composant MDX inconnu (liste les
composants disponibles), MDX mal formé (ligne:colonne), type JSON-LD inconnu,
thème inconnu, `siteUrl` invalide, dossier absent, config JS invalide, version
inconnue (`build v9.9` → exit 1). Tous ces cas arrêtent le build avec un
message et une piste. `serve` résiste à la traversée de répertoire (`../`,
`%2e%2e`). La recherche échappe correctement une requête
`<img src=x onerror=…>`.

Remarque : du HTML brut (`<script>`) dans un `.md` passe tel quel dans la
page. Normal pour un contenu de confiance, mais à documenter si plusieurs
personnes écrivent la doc.

## 5. SEO

### 5.1 Ce qui est bien fait ✅

- `<title>` « Page · Projet », `<meta name="description">` depuis le frontmatter.
- `<link rel="canonical">` absolu dès que `siteUrl` est défini.
- Open Graph complet + `twitter:card summary_large_image` quand `socialImage` est
  défini.
- `hreflang` (`en`, `fr`, `x-default`) croisés et absolus sur les pages traduites ;
  `<html lang="fr">` et interface traduite (placeholder, aria-labels).
- Version bêta (`prerelease`) : `noindex, follow`, exclue du sitemap et du RSS.
- `sitemap.xml` avec `lastmod` quand une date existe ; RSS 2.0 valide avec
  `atom:link self`.
- JSON-LD `@graph` : `Organization` (+ logo), `TechArticle`/`Article`,
  `BreadcrumbList`, `Person` pour les auteurs.
- Page de recherche en `noindex`, un seul `<h1>` par page, lien d'évitement.

### 5.2 Manques

| #   | Gravité | Constat                                                                                                                                                                                                                       |
| --- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1  | 🟠      | **Pas de page 404** (`404.html`) : GitHub Pages, Netlify, Cloudflare servent alors leur page générique, sans navigation vers la doc.                                                                                          |
| S2  | 🟠      | **Sans `siteUrl` (défaut d'`init`), le JSON-LD a des `@id` relatifs** (`/#organization`) et aucune canonical : données structurées invalides pour Google. Un avertissement au build serait utile tant que `siteUrl` est vide. |
| S3  | 🟡      | **Redirection racine par `<meta refresh>`** avec une canonical **relative** (`/proj/versions/v1.0/`) même quand `siteUrl` est connu. La rendre absolue.                                                                       |
| S4  | 🟡      | **Versions archivées indexées avec une canonical vers elles-mêmes** : le même contenu en 0.9 et 1.0 se concurrence. Option : canonical de l'archive vers la page équivalente de la version courante quand elle existe.        |
| S5  | 🟡      | `og:type` vaut toujours `website` (même pour un article) ; pas d'`og:locale` sur les pages FR.                                                                                                                                |
| S6  | 🟡      | JSON-LD sans `inLanguage` (pages FR notamment) ; le fil d'Ariane reste « Home » en anglais sur les pages FR.                                                                                                                  |
| S7  | 🟡      | Pas de favicon par défaut → **404 `/favicon.ico` sur chaque page** (erreur console, −4 pts « Bonnes pratiques »).                                                                                                             |
| S8  | ℹ️      | `/guide/installation` (sans `/` final) renvoie 200 avec le même contenu au lieu de rediriger vers la forme canonique (côté `serve` ; dépend de l'hébergeur en prod).                                                          |
| S9  | ℹ️      | `robots.txt` n'est écrit que si le site est à la racine du domaine : logique, mais `docs.example.com/proj` n'aura aucun lien vers le sitemap. Le signaler au build.                                                           |

## 6. GEO (optimisation pour les moteurs génératifs / agents IA)

Lighthouse (catégorie « agentic-browsing ») : 100 sur le site Tailwind, 50 sur
le site custom sous sous-chemin.

| #   | Gravité | Constat                                                                                                                                                                                                                              |
| --- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| G1  | 🟠      | **Pas de `llms.txt`** (ni `llms-full.txt`). Pour un outil de documentation, c'est aujourd'hui la convention attendue par les assistants IA ; tout est déjà là pour le générer (titres, descriptions, arbre de navigation, versions). |
| G2  | 🟠      | **Pas de version Markdown des pages** (`index.md` à côté de `index.html`) : les agents doivent parser un HTML dont la moitié est de la classe Tailwind (cf. P1).                                                                     |
| G3  | 🟡      | JSON-LD sans `inLanguage`, `version`/`softwareVersion`, ni `isPartOf` (`WebSite`) : les moteurs ne peuvent pas relier une page à sa version et à sa langue.                                                                          |
| G4  | ✅      | Points forts : HTML sans JS (contenu lisible directement), descriptions systématiques, dates, auteurs, fil d'Ariane, arbre d'accessibilité propre.                                                                                   |

## 7. Ergonomie et accessibilité

### 7.1 Ce qui marche ✅

- Messages d'erreur remarquables : quoi, où, et comment corriger.
- Config générée entièrement commentée, lisible sans ouvrir la doc.
- Bouton clair / sombre : bascule, `localStorage`, persistance après
  rechargement, sans flash (script inline dans `<head>`).
- Recherche : fonctionne, préfixes (`instal` → 21 pages), sans JS la page liste
  toutes les pages (repli propre).
- Première tabulation → « Skip to content » ; `aria-current`, `aria-label`
  traduits.
- Pas de débordement horizontal à 375 px.

### 7.2 Problèmes (axe-core, WCAG 2.2 AA, clair/sombre × mobile/desktop)

| #   | Gravité | Constat                                                                                                                                                                                                                                                 |
| --- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | 🟠      | **Contrastes insuffisants (Tailwind)** : `slate-500` (#62748e) sur fond sombre #020618 = **4,23:1** pour les titres de section du menu et le pied de page ; sur `indigo-50` = 4,26:1 pour les `.dp-tag` et les `<mark>` de la recherche. Il faut 4,5:1. |
| E2  | 🟠      | **Liens indiscernables sans la couleur** : lien `#4f39f6` dans du texte `#0f172b`, 2,75:1 et sans soulignement (WCAG 1.4.1).                                                                                                                            |
| E3  | 🟡      | Coloration Shiki : commentaires `#6a737d` sur `#24292e` = 3,04:1 (sombre), `#e36209` sur blanc = 3,48:1 (clair). Choisir un thème Shiki conforme AA.                                                                                                    |
| E4  | 🟡      | Plusieurs `role="region" aria-label="Scrollable table"` identiques par page : landmarks non distinguables. Nommer par la légende ou le titre qui précède.                                                                                               |
| E5  | 🟡      | Tableaux larges sans `<th>` associés (`td-has-header`, page API).                                                                                                                                                                                       |
| E6  | 🟡      | Bouton « retour en haut » hors de tout landmark.                                                                                                                                                                                                        |
| E7  | 🟡      | **Changer de version renvoie à l'accueil de la version** et non à la même page (depuis `guide/installation`, tous les liens vont vers `/versions/vX/`) : on perd sa place.                                                                              |
| E8  | 🟡      | Sur mobile, deux menus : le hamburger (versions, langue, liens) et « Documentation menu » (navigation). On ne devine pas lequel ouvrir.                                                                                                                 |
| E9  | ℹ️      | Recherche : pas de tolérance aux fautes (`instalation` → 0 résultat) ; les extraits contiennent des artefacts de code (`theme : { framework : 'tailwind' ,`).                                                                                           |
| E10 | ℹ️      | La byline (auteur, date) précède le `<h1>` dans `<main>`.                                                                                                                                                                                               |

1. **B1** — dates impossibles acceptées en silence (données fausses publiées dans le JSON-LD et le sitemap).

3. **B3 + D1** — valider les clés de config inconnues, ou corriger le README ; option `build --strict` qui enchaîne `check`.
4. **Publier la 0.5** (corrige B10, l'écoute sur toutes les interfaces).
5. **E1/E2** — contrastes du thème Tailwind (conformité AA).
6. **S1, S2, G1** — `404.html`, avertissement si `siteUrl` est vide, `llms.txt`.
7. **P1** — alléger les classes répétées du shell Tailwind.
