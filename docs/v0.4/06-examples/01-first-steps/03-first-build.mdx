Each page is a complete file, served as it is. A page is a **folder** holding
an `index.html`, which is what gives it an address ending in a slash and
needs no rule on the server. The <Tooltip text="The only stylesheet of the site, compiled from the classes the pages use.">stylesheet</Tooltip> comes along; no script does.

## When something is wrong

`build` stops on what it cannot do — a missing file, a component used wrongly —
and names it. It says nothing about a link pointing at a page you renamed:
that page compiled perfectly, it simply is not there any more.

```bash
npx docpensieve check
```

<Admonition type="tip" title="Run it every time">
  `check` reads the built site back and exits with an error if a link leads nowhere. It costs a
  second, and it is the difference between finding a dead link yourself and having a reader find it.
</Admonition>

## While you write

```bash
npx docpensieve dev
```

It serves the site and rebuilds on every save — including when you change the
configuration or a file of the `theme/` folder. Leave it running in a second
terminal: the loop between writing a sentence and seeing it is what makes a
documentation get written.
