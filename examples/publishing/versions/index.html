Versions

Module progress33%

Lesson 1 of 3.

Your product moves. Your readers do not all move with it: some run the version you shipped last spring. A documentation that only describes today lies to them.

Two tracks

latest
The version readers get by default. It only receives fixes.
beta

The version being written. Its pages carry a banner, and stay out of search engines.

The address names the channellatest or beta: the role of the version, not its number — so a shared link stays right., the menu shows the exact number.

Your turn: declare them

A version is a folder of pages and an entry in the configuration:

versions: [
  { slug: 'beta', name: '2.0 (beta)', folder: 'docs/v2.0', prerelease: true },
  { slug: 'latest', name: '1.4', folder: 'docs/v1.4', current: true },
  { slug: 'v1.3', name: '1.3', folder: 'docs/v1.3', archived: true },
],
  • my-course
    • docs
      • v1.3 — frozen
      • v1.4 — what readers get
      • v2.0 — what you are writing

Each folder stands on its own: its own pages, its own images, its own menu. A fix that matters to both tracks is written twice — which sounds like a chore until the first time an edit to today's page would have rewritten history.

Why the slug says the channel, not the number

A link to /versions/v1.4/guide/ goes stale the day 1.5 ships. A link to /versions/latest/guide/ stays right forever. The number belongs in the label the menu shows — and in the address only once a version is frozen, because then it stops moving.

Swapping them, the day you ship

Three edits, in this order:

  1. The beta becomes the current version: slug: 'latest', current: true, and prerelease goes away.
  2. The version it replaces is archived under its number: slug: 'v1.4', archived: true.
  3. A new beta folder opens, copied from the one just promoted.

The logo of the promoted version

Fields like logo follow the configuration, but an image sitting inside a version folder does not: a home page that showed a beta banner keeps showing it. This site learned that the hard way — it published a promoted version still wearing the beta logo, and a reader saw it first.

A banner that follows the calendar

A notice can announce a release and remove itself once it is out — no diary entry, no forgotten banner:

A new version is in preparation. Try it on the beta channel.
<TimeTimer start="01/09/2026" duration="60d">
  A new version is in preparation.
  <FallbackAfter>The new version is out.</FallbackAfter>
</TimeTimer>

Check yourself

What does a prerelease version change, besides the banner?

It stays out of the sitemap and asks search engines not to index it — a reader arriving from a search lands on the version that is actually shipped.

You renamed a version's slug. What happens to the links people shared?

They break: the slug is the address. This is the whole reason a channel slug — latest, beta — is worth more than a number, and why an archived version takes its number only once its content stops moving.

This lesson uses TimeTimer, Tooltip, Tree, Admonition and Card — and the versions guide goes through the whole cycle.
